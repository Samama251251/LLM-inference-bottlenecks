Why two phases at all

Prefill · one wide pass

512 tokens at once

Processes the whole prompt in a single forward pass. Each weight it loads is reused across 512 tokens, so the work per byte moved is high: intensity ~511 FLOP/byte. That lands it right of the ridge, against the compute ceiling. More FLOPs (longer prompt, bigger model) cost more time. This is the TTFT lever.

Decode · 255 skinny passes

1 token at a time

Autoregressive: each token needs the previous one, so it runs the pass once per output token. At batch 1 it re-reads the entire 3 GB of weights to make a single token: intensity ~1 FLOP/byte. That pins it to the bandwidth roof, far left. FLOPs are irrelevant here; bytes/sec is everything. This is the TPOT lever, and it is what batching attacks.
